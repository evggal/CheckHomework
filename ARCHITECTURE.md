## 📊 Поток обработки (Processing Pipeline)

```
1. Фронтэнд отправляет запрос
   ├─ image_name: "matrix_1.jpg"
   └─ timestamp: "2024-12-21T16:30:45"

2. Backend получает WebSocket сообщение
   ├─ Проверяет наличие картинки в БД
   └─ Отправляет: status=started

3. Имитация обработки (5 этапов)
   ├─ loading_model (1 сек) → 15% прогресса
   ├─ preprocessing (1.2 сек) → 35%
   ├─ ocr_recognition (1.5 сек) → 60%
   ├─ solution_analysis (0.8 сек) → 85%
   └─ finalizing (0.5 сек) → 100%

4. Получение данных из БД для картинки
   ├─ text_recognized: bool
   ├─ solution_correct: bool/None
   └─ solution_path: str/None

5. Загрузка решения (если есть)
   └─ solution_content из SOLUTIONS словаря

6. Отправка результата на фронтэнд
   ├─ status: "completed"
   ├─ progress: 100
   ├─ data с полной информацией
   └─ solution_content в виде текста

7. Фронтэнд отображает результаты
   ├─ Прогресс-бар
   ├─ Результаты
   └─ Решение в псевдографике
```

## 🚀 Масштабируемость

### Текущий дизайн
- ✅ Асинхронная обработка (FastAPI/asyncio)
- ✅ WebSocket для real-time (не требует polling)
- ✅ Stateless (можно запустить несколько инстансов)
- ✅ Простой in-memory DB (легко заменить на PostgreSQL)

### Как масштабировать:

